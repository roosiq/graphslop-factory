# Data Model: Graphslop Graph Kernel and Control Plane

**Authority**: `intent-v1`  
**Solution**: proposed `solution-v1`  
**Canonical format**: strict JSON validated before use and canonicalized before hashing

## Common Identifiers

All IDs are generated by deterministic control-plane code, never accepted as authoritative model
output.

| Kind | Format | Example |
|---|---|---|
| Project | `project_<slug>` | `project_graphslop` |
| Graph | `<kind>-graph-<version>` | `intent-graph-3` |
| Snapshot | `snapshot_<sha256-prefix>` | `snapshot_a381...` |
| Stable node | kind-specific readable prefix plus UUID | `intent_goal_...` |
| Node version | stable node ID plus positive integer | `intent_goal_...@2` |
| Edge | `<graph-kind>_edge_<uuid>` | `intent_edge_...` |
| Baseline | `<graph-kind>-v<number>` | `intent-v1` |
| Transformation | `transform_<uuid>` | `transform_...` |
| Task | `task_<slug>_<uuid>` | `task_graph-kernel_...` |

## GraphSnapshot

```text
schemaVersion        non-empty semantic contract version
graphKind            intent | solution | execution
graphId               stable graph identifier
snapshotId            derived from content hash
revision              positive monotonic integer
parentSnapshotId      null only for revision 1
createdAt             RFC 3339 timestamp assigned by control plane
createdBy             ActorRef
nodes                 complete set of all retained node versions
edges                 complete set of all retained edge versions
crossGraphLinks       exact versioned references into other approved graphs
contentHash           SHA-256 of RFC 8785 canonical snapshot without this field
```

Validation:

- `revision = parent.revision + 1`.
- `parentSnapshotId` and expected parent hash must match the current head.
- Node and edge IDs are unique within a graph.
- Every edge endpoint resolves to a node version retained by the snapshot.
- Cross-graph links name exact graph, snapshot, node, and node version.
- Set-like arrays are sorted by stable keys before canonicalization.
- Approved snapshot files are never changed or deleted by normal product operations.

## GraphNode

Common fields:

```text
id, stableId, version, type, status, statementOrName,
createdAt, updatedAt, sourceRefs, actorRef, attributes
```

Intent nodes add:

```text
sourceQuote, originalInterpretation, normalizedInterpretation,
confidence, approvedByUser, baselineMembership
```

Intent node status is exactly:

```text
inferred | proposed | confirmed | rejected | superseded | unresolved | deferred
```

Solution nodes add:

```text
scope                 product | implementation_support
satisfies             exact Intent NodeRef[] when scope=product
supports              exact Solution NodeRef[] when scope=implementation_support
```

Execution nodes add the complete TaskContract described below.

## GraphEdge

```text
id, version, type, sourceNodeRef, targetNodeRef,
status, createdAt, updatedAt, sourceRefs, attributes
```

Intent edge types and Intent node types are exactly the enumerations in NC-001 and NC-002.
The graph kernel owns an explicit compatibility table for legal source and target types.

`SUPERSEDES` is directed from the new version to the old version. `CONTRADICTS` is symmetric in
meaning but stored once in stable lexical endpoint order. Resolving a contradiction transitions
the edge state and requires an exact confirmed Decision reference; it never removes the edge.

## CrossGraphLink

```text
id
type                  SATISFIES_INTENT | SATISFIES_SOLUTION
source                exact target-graph NodeRef
target                exact approved source-graph NodeRef
sourceBaselineId
targetBaselineId
createdAt
transformationId
```

Validation rejects a product-facing Solution node without `SATISFIES_INTENT`, an Execution task
without `SATISFIES_SOLUTION`, or a link to an unapproved or stale source snapshot.

Project lifecycle:

```text
CAPTURE
→ DISCOVERY
→ INTENT_REVIEW
→ INTENT_APPROVED
→ SOLUTION_GENERATION
→ SOLUTION_REVIEW
→ SOLUTION_APPROVED
→ EXECUTION
```

## TaskContract

```text
taskId
taskType              Inspect | Decide | Implement | Test | Verify | Integrate | Repair | Document | Release
objective             one sentence
status
satisfiesSolutionRefs[]
protectedIntentBaseline
protectedSolutionBaseline
dependencies[]
allowedPaths[]
forbiddenChanges[]
requiredOutputs[]
acceptanceChecks[]
retryPolicy
requiredEvidence[]
producerAssignment
verifierAssignment
createdAt
updatedAt
```

Execution dependencies must form a DAG. Stable topological order sorts equal-ready tasks by task ID.

Task status:

```text
proposed → blocked → ready → authorized → leased → running → produced
→ verifying → accepted
                 ↘ failed → repair_proposed
proposed|blocked|ready → discarded
```

Only one task may be `leased`, `running`, `produced`, or `verifying` at a time.

```text

baseCommit, candidateCommit, producerInvocationId, outcome,

```

A result cannot advance state when the lease is expired, cancelled, duplicated, stale, incorrectly
signed, for another task, or tied to another baseline, graph, repository, or base commit.

## File-Store Commit Protocol

1. Acquire the single project-writer lock.
2. Read and verify `head.json` and its referenced snapshot hash.
3. Require the mutation’s expected base hash to match.
4. Validate and canonicalize the delta.
5. Apply it as a pure function and validate the complete target snapshot.
6. Write delta, snapshot, transformation, and projection temporary files.
7. Flush and atomically rename immutable artifacts.
8. Write and atomically replace `head.json` last.
9. Append the redaction-safe audit event.
10. Release the lock.

A crash before step 8 may leave unreachable immutable files, which startup recovery quarantines.
A crash after step 8 exposes a complete verified snapshot.
